# I-Worm.Kevlar — Technical Analysis (2001)

> Research/education only. This document analyzes a historical worm for defensive understanding and archival. It does not provide operational build/run instructions.

## Overview

I‑Worm.Kevlar is a 32‑bit Windows worm from August 2001, written in TASM/MASM‑style assembly and (per comments) optionally UPX‑packed. It installs two copies in the System directory, persists via HKLM Run, marks selected EXE files with a short signature, creates companion HTML files (ActiveX/VBScript lure), and spreads through email using a two‑stage process: a VBScript that harvests Outlook addresses into a file and native code that parses this file and sends mail via Simple MAPI with a copy of itself attached.

Source: `Kevlar.asm` (includes `useful.inc` macros)

## Installation and persistence

- Drops two executables in the System directory:
  - `%System%\Kevlar32.exe` — sets FILE_ATTRIBUTE_HIDDEN.
  - `%System%\MScfg32.exe` — normal attributes; later used as the email attachment.
- Registry autorun (all users):
  - Dynamically loads `SHLWAPI.dll` and resolves `SHSetValueA`.
  - Writes `HKLM\Software\Microsoft\Windows\CurrentVersion\Run\Kevlar32 = %System%\Kevlar32.exe`.

## User‑visible decoy

- Generates a random 9‑character uppercase nickname using `GetTickCount` arithmetic and short `Sleep` calls.
- Shows a MessageBox (`MB_ICONINFORMATION`) with caption: "Hello, my name is :" and the generated nickname as the text.

## File “infection” behaviors

1) Marker infection of Windows "C???????.exe"
- Operates in `%WinDir%` and enumerates files matching `C???????.exe`.
- Opens each file with read/write mapping and performs header checks (MZ/PE heuristics), then writes the marker string "PetiK" at bytes 0x12–0x16 of the DOS header if not present already.
- Logs each successful mark to `%WinDir%\MSinfo32.txt` using INI format: section `[File Infected]`, key `<filename>`, value `Infected by W32.Kevlar.PetiK`.

2) Companion HTML for every EXE
- Still in `%WinDir%`, iterates `*.exe` and creates a sibling file named `<original>.exe.htm` containing an HTML page with VBScript.
- The page is a simple lure ("This page is generated by a worm…") and includes a line attempting to set Internet Explorer Start Page to `http://www.avp.ch` via `RegWrite` (HKCU scope). It does not auto‑execute the binary; it’s primarily social engineering.

## Email harvesting and mass mailing

Two‑stage approach:

A) Address book harvest (VBScript)
- Drops `C:\__.vbs` with script that uses Outlook OOM: enumerates all AddressLists and AddressEntries, appending `P.Address` to `%WinDir%\AddBook.txt`.
- After harvesting, writes a sentinel line with a single `!` to mark end of list.
- Executes via `wscript C:\__.vbs`, sleeps briefly, then deletes the script.

B) Native scan and Simple MAPI send
- Opens `%WinDir%\AddBook.txt` via file mapping and parses it line‑by‑line until the `!` marker.
- For each non‑empty line, treats it as an email address, records it under `[EMail saved]` in `%WinDir%\MSinfo32.txt` as `<address>=Next victim`, and sends an email using `MAPISendMail` with:
  - Subject: "Windows Protect !!"
  - Body: A short lure text referencing "WWW.KEVLAR-PROTECT.COM" and an attachment.
  - Attachment: `%System%\MScfg32.exe` (the second installed copy).
- Uses `lhSession = 0` for `MAPISendMail` (no prior `MAPILogon`), relying on Simple MAPI to send through the default profile.

## Artifacts and IOCs

Files:
- `%System%\Kevlar32.exe` (hidden; main persistence target)
- `%System%\MScfg32.exe` (attachment used for mass mail)
- `%WinDir%\MSinfo32.txt` (INI file; sections `[File Infected]` and `[EMail saved]`)
- `%WinDir%\AddBook.txt` (harvested addresses from Outlook)
- `%WinDir%\*.exe.htm` (companion HTML files for every EXE in `%WinDir%`)
- `C:\__.vbs` (temporary harvester script)

Registry:
- `HKLM\Software\Microsoft\Windows\CurrentVersion\Run\Kevlar32 = %System%\Kevlar32.exe`
- The HTML lure attempts: `HKCU\Software\Microsoft\Internet Explorer\Main\Start Page = http://www.avp.ch` (from within the browser context if ActiveX/VBScript enabled).

User‑visible:
- MessageBox caption: "Hello, my name is :" and a random uppercase nickname of 9 characters.

Network/email:
- No raw sockets; sending is via Simple MAPI using the local email client profile.

## Code quirks and notes

- The "infection" of `C???????.exe` only writes a textual marker into the DOS header; it does not add code to host executables. This is mostly a tag and a log entry.
- Companion `.exe.htm` files are created in `%WinDir%` only; no autorun mechanism ties them to the original EXEs beyond social‑engineering file name.
- Registry writes use SHLWAPI `SHSetValueA`, a compact way to set HKLM Run without full Advapi32 sequences.
- Email harvesting uses Outlook OOM in a VBScript (safer to block via WSH policies); sending uses Simple MAPI, which may prompt or auto‑send depending on the client’s security settings of that era.

## Annex — USEFUL.INC macro usage

- `@pushsz "..."` — inline push of a zero‑terminated string literal (saves separate data declarations).
- `callx ApiName` — macro that declares `extrn ApiName:proc` and calls it, keeping the assembly tidy.
- Standard stdcall pattern is used: arguments are built with `push` in reverse order, then `callx` invokes the API.

## Defensive guidance (historical)

- Remove persistence: delete the HKLM Run value `Kevlar32` referencing `Kevlar32.exe`.
- Clean files: delete `%System%\Kevlar32.exe`, `%System%\MScfg32.exe`, `%WinDir%\*.exe.htm`, `%WinDir%\MSinfo32.txt`, `%WinDir%\AddBook.txt`, and `C:\__.vbs` if present.
- Undo browser changes: verify/restore IE home page under HKCU if the HTML page ran.
- Outlook/WSH hardening: block or restrict Windows Script Host and Outlook COM automation; use modern email client protections against programmatic sends.
- Gateway controls: block executable attachments and double‑extension patterns.

## Build notes (from source header)

- Assemble/link: `tasm32`, `tlink32`; optional packing with `upx`.
